# Final-Year Engineering Project Guidelines (Academic Year 2024-2025)

## 1. Introduction and Objectives
The Final-Year Capstone Project is the culminating academic requirement for Bachelor of Engineering (B.E./B.Tech) students. The objective is to design, develop, test, and demonstrate an innovative engineering solution addressing real-world problems.

## 2. Project Lifecycle & Milestone Timeline
The project spans two semesters across four defined phases:

- **Phase 1: Project Proposal & Synopsis Submission (Week 1-3)**
  - Submission of 3-page project synopsis.
  - Team composition: 3 to 4 students per team.
  - Identification of Faculty Guide and Domain Co-Guide.
  - Initial feasibility and technology readiness assessment (TRA).

- **Phase 2: Architectural Design & Mid-Semester Review (Week 4-8)**
  - Software Architecture Document (SAD) with C4/UML diagrams.
  - Database schema normalization and OpenAPI/REST specifications.
  - Mid-semester viva voce examination (30% weightage).

- **Phase 3: Implementation & Continuous Integration (Week 9-14)**
  - Complete implementation of core functional modules.
  - Test-Driven Development (TDD) with unit testing coverage exceeding 80%.
  - Integration of automated CI/CD pipeline using GitHub Actions.

- **Phase 4: Final Demonstration, Thesis & Viva Voce (Week 15-18)**
  - Final working system demonstration to external examiners.
  - Plagiarism check: Thesis similarity index must not exceed 15% (Turnitin/Urkund).
  - IEEE/Springer format research paper draft submission.

## 3. Mandatory Engineering Deliverables
Every project team must deliver:
1. **GitHub Repository**: Structured monorepo or microservices with clean git commit history following conventional commits.
2. **Dockerization**: Complete containerization with `docker-compose.yml` for single-command deployment.
3. **Automated Test Suite**: Unit tests, integration tests, and performance benchmark logs.
4. **Project Thesis**: Formatted strictly according to the University Thesis Manual in LaTeX or Word.

## 4. Academic Integrity and Plagiarism Policy
- Projects using copied, unoriginal repositories or purchased projects will receive an immediate 'F' grade.
- Open-source libraries must be explicitly credited in the project bibliography.
- Generative AI assistance must be declared with prompts documented in the appendix.
